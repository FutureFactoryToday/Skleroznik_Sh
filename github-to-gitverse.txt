Шаг 1. 	Подготовка пустого репозитория на GitVerse
		
			Перед отправкой кода сервер должен знать, куда его сохранить.
			Зайдите на сайт GitVerse.
			В правом верхнем углу нажмите кнопку «+» и выберите «Новый репозиторий».
			В поле «Название репозитория» введите имя проекта (рекомендуется использовать то же имя, что и на GitHub).
			⚠️ Важно: Не ставьте галочки «Инициализировать репозиторий», «Создать README» или «Добавить .gitignore». Репозиторий на сайте должен остаться абсолютно пустым, иначе сервер отклонит перенос истории.
			Нажмите кнопку «Создать репозиторий».

Шаг 2. 	Получение токена доступа
		
			Для безопасной отправки кода из консоли без ввода пароля понадобится персональный токен.
			В правом верхнем углу GitVerse нажмите на свой аватар и перейдите в «Настройки».
			В левом меню выберите пункт «Управление токенами».
			Введите любое название для токена (например, migration), отметьте галочку «Репозитории» и нажмите «Генерировать токен».
			Скопируйте и сохраните полученную строку (на сайте она показывается только один раз).

Шаг 3. 	Перенос кода через Git Bash
		
		Откройте терминал Git Bash на компьютере и выполните три команды по очереди.
		Для удобства перед запуском замените в шаблоне ниже:
		ИМЯ_ОРГАНИЗАЦИИ_ИЛИ_АВТОРА — имя владельца репозитория на GitHub.
		ИМЯ_РЕПОЗИТОРИЯ — точное название переносимого репозитория.
		ВАШ_ЛОГИН — ваш никнейм на GitVerse.
		ВАШ_ТОКЕН — длинная строка, скопированная на Шаге 2.
		
		1. Скачивание полного зеркала проекта с GitHub:

				git clone --mirror github.com
				(Эта команда скачает специальную bare-копию проекта со всеми скрытыми ветками, релизами и хронологией).
		
		2. Переход в созданную системную папку:

				cd ИМЯ_РЕПОЗИТОРИЯ.git
		
		3. Отправка всех данных на GitVerse:

				git push --mirror https://ВАШ_ЛОГИН:ВАШ_ТОКЕН@gitverse.ru/ВАШ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ.git

Шаг 4. 	Очистка компьютера (необязательно)
		После того как в консоли отобразится 100% и завершится отправка, локальную временную папку на компьютере можно удалить, чтобы она не занимала место:

		cd ..
		rm -rf ИМЯ_РЕПОЗИТОРИЯ.git

💡 Полезный совет
Если при отправке (git push) в консоли появляются красные строчки с ошибками hook declined для путей вида refs/pull/... — не обращайте внимания. Это встроенная защита GitVerse: она блокирует перенос внутренних служебных ссылок GitHub на чужие закрытые Pull Request-ы. Весь ваш исходный код, ветки и теги при этом переносятся успешно.
Если вы планируете настроить автоматическое обновление этого репозитория по расписанию, чтобы новые коммиты с GitHub сами прилетали на GitVerse, дайте знать. Я опишу, как настроить простую автоматизацию.
